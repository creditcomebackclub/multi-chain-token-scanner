# Free-feed reliability: research, plan, rollout

## Evidence
On September 16 the deployed scanner reported 10 of 20 chart refreshes successful, Telegram healthy, and repeated HTTP 429 responses. The deployed HTTP client already honors Retry-After, with a 60-second fallback only when absent or malformed. Short Retry-After values can permit another attempt after the normal nine-second pacing. We have not captured the offending response headers or proven whether shared egress contributes.

Official GeckoTerminal documentation says approximately ten calls/minute, variable with traffic, with one-minute endpoint caching: https://api.geckoterminal.com/docs/index.html
CoinGecko pricing lists Demo 10,000 monthly credits, Basic $35 monthly / 100,000 credits, Analyst $129 monthly / 500,000 credits: https://www.coingecko.com/en/api/pricing
These are alternatives, not subscriptions purchased or configured. Paid endpoint entitlement, chain coverage and credit cost must be verified before subscribing. Twenty pools at one request every five minutes alone require 172,800 calls in 30 days, exceeding Basic included calls before discovery or retries. The free Demo cap is not a substitute for continuous scanning.

## Implemented plan
- Shared free-feed starts spaced at least 12 seconds (five/minute peak).
- HTTP 429 enforces max(provider Retry-After, 60 seconds) for the shared free-feed queue, including callers other than the failed request. Existing Bitquery behavior unchanged.
- Ten chart requests per five-minute cycle, drawn from a daily twenty-pair watchlist. Five oldest attempts guarantee rotation; remaining slots prioritize recently developing setups and then older attempts. All pairs receive a turn within four uninterrupted successful cycles; this is not twenty charts every five minutes.
- Discovery every fifteen minutes, chart schedule independent with per-worker non-overlap guards. Both still use the same HTTP queue.
- Rotate discovery chain order to avoid repeatedly penalizing the same chains on timeouts. Preserve the two-minute discovery-data freshness cutoff and all market/security rules.
- Bounded 285-second worker budgets. Abort-aware cooldown prevents deadline exhaustion from launching extra calls.
- Health and /setups report attempted, successful and deferred work honestly.

Nominal free-feed requests fall from 30/5 minutes (259,200/30 days) to 10/5 + 10/15 (115,200/30 days), before failed cycles/retries: about 56% fewer calls. No candle cache added: each selected pool is fetched only once per cycle and the five-minute revisit already exceeds the provider's one-minute cache. Serving older cached candles as current would be misleading.

## Scope and limitations
BUY signal rules, market/security checks, stale-data suppression, entry expiry and cap remain unchanged. No historical alerts are replayed. A provider can still throttle below the documented approximation; this change does not guarantee profitable signals or a daily quota. Reduced refresh frequency can miss short-lived patterns. Separate exit alerts and trading execution remain absent.

### Live validation and second adjustment
Initial rollout ffb29b88-e218-48f7-a21c-bb942f3feda4 completed a chart cycle with 9/10 fresh usable responses (one stale-candle rejection), versus baseline 10/20 and repeated 429s. All ten discovery endpoints responded, but overlapping workers made early responses exceed the preserved two-minute freshness cutoff. Consequently discovery startup/repeats are now offset by 2.5 minutes from five-minute chart cycles. This schedules normal 120-second chart and discovery batches in separate portions of the cycle, retaining the same shared queue and deadline behavior under slow responses.

Final build and all 98 tests passed, including cooldown, fairness, persisted entry-plan, stale-data/security gates, phased startup/repeat, and shutdown-before-start checks. No subscription, credential purchase, or trade execution enabled. Early results establish operation, not a long-term availability guarantee.

DEX Screener's documented pair endpoint permits 300 requests/minute, but its public reference is market snapshots rather than a documented historical OHLCV replacement; current exact-pool enrichment remains in use: https://docs.dexscreener.com/api/reference

Final deployment 80e4c4c1-ae54-4183-81c5-111a5455da83: Railway SUCCESS; phased code present, chart/push enabled, pause false. Temporary SSH audit key revoked and removed.

### Sustained production verification

Later production verification on the same deployment showed chart health `healthy`: 10/10 attempted charts had fresh usable five-minute candles, zero refresh failures, and ten deferred for the next rotating cycle. All twenty saved chart states were 2–13 minutes old, with no current HTTP 429 state. All five discovery chains reported both public endpoints available, and Telegram polling remained healthy. No chart BUY alert had been sent since deployment because no candidate had passed the full setup and safety gates. This verifies feed scheduling and rotation; it does not guarantee that the public provider will never throttle future traffic.
